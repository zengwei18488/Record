這五個檔案共同構成了一套完整的 Cellular Guard 工業級 4G 網路保活、四級階梯自癒與低功耗休眠喚醒架構。它將「撥號執行」、「前置體檢」、「階梯退避自癒」、「無卡低功耗待機」以及「系統休眠／喚醒協同」徹底解耦，完全不依賴整機重啟即可應對各種基站或模組異常。

一、 系統架構與檔案職責分工


檔案角色	檔案對應	核心職責與設計亮點
1. 參數配置層	cellular_env.conf	集中管理巡檢週期（600s）、四檔退避間隔（60s -> 1200s -> 3600s -> 3600s）、失敗閾值（3 -> 3 -> 5 -> 12）、防抖重置時間（1800s）、雙線 PING 目標、Mini PCIe 硬體復位節點與日誌上限（100KB）。
2. 撥號執行層	quectel-cm.service	負責純粹的 QMI 撥號工作。啟動前自動檢查 USB idVendor=2c7c 移遠設備是否存在，無模組時優雅退出不佔用資源；意外崩潰時 2 秒 內自動拉起。
3. 決策監控層	quectel-watchdog.service + quectel-watchdog.sh	系統大腦。具備開機前檢、進程守護、雙線連通性檢測、四級硬體漸進自癒、指數級退避（防風暴）以及無卡低頻待機機制。
4. 休眠協同層	quectel-sleep hook	系統級電源管理鉤子（pre 休眠前 / post 喚醒後）。休眠前釋放串口、開啟 AT+QSCLK=1 慢時鐘模式與 USB 自動掛起；喚醒後透過 systemd-run 脫離睡眠 cgroup 安全恢復撥號與看門狗。


二、 核心狀態機與自癒工作流解析


1. 開機前檢與無卡低功耗待機（query_modem_and_sim & standby_polling_loop）

• 開機前檢：看門狗啟動後先延遲 15s 等待驅動就緒，若未檢測到 2c7c 移遠模組則直接優雅退出，節省無模組機型的系統資源。
• 四態精準識別：透過 AT 指令（AT+CPIN?、AT+CEREG?、AT+CSQ）精準區分四種狀態：
	• 0（就緒）：SIM 卡正常、已駐網且信號有效（CSQ >= 1），立即啟動 quectel-cm 撥號。
	• 1（無卡）：連續兩次確認無 SIM 卡（CME ERROR: 10/13），停止撥號進程並進入 30s 低頻待機輪詢，避免無卡時頻繁無效重試或誤觸發硬體復位。
	• 3（待註冊/弱信號）：SIM 卡就緒但尚未註冊基站，持續低頻等待駐網。
	• 2（模組異常/串口無響應）：累計失敗達到閾值後，在待機模式下也會自動依序執行 AT+CFUN=1,1 軟復位 -> USB 總線重綁 -> Mini PCIe 硬體復位。

2. 雙線連通性檢測與進程秒級守護（check_internet & ensure_cm_running）

• 進程守護：在主循環的 5s 細粒度睡眠切片中持續檢查 quectel-CM 進程是否存活；若異常退出則立即拉起，連續崩潰達 MAX_CM_CRASHES=3 次時轉入待機保護狀態。
• 雙目標防誤判：同時檢測 wwan0 是否具備有效 IPv4 地址，並依次向 223.5.5.5 與 114.114.114.114 發送 PING 探測（任一通即判定正常），避免單一 DNS 節點故障導致誤觸發恢復。

3. 四級漸進式自癒與退避算法（Anti-Storm & Anti-Flapping）

當網路連通性持續失敗時，系統不會盲目重複重啟，而是結合 退避階梯（GRADIENT_IDX） 與 恢復深度（RECOVERY_STAGE） 逐級升級處置：
• 第一級（Stage 1，累計失敗 3 次 / 間隔 60s）：重啟 quectel-cm.service 撥號服務，解決營運商基站釋放閒置 PDP 通道或 IP 租約過期問題（最輕量、零斷流）。
• 第二級（Stage 2，累計失敗 3 次 / 間隔 1200s）：停止撥號並發送 AT+CFUN=1,1 軟復位 4G 模組協議棧，解決模組射頻駐網卡死。
• 第三級（Stage 3，累計失敗 5 次 / 間隔 3600s）：對 2c7c USB 設備執行底層驅動 unbind -> bind 總線重綁，解決 Linux 內核 qmi_wwan 或 USB 端點掛死。
• 第四級（Stage 4，累計失敗 12 次 / 間隔 3600s）：拉動硬體節點 echo 1 > /sys/devices/platform/misc-adv-gpio/minipcie_reset 對 4G 模組執行冷斷電硬體復位，隨後轉入低功耗待機輪詢等待基站恢復。
• 防抖動重置（Anti-Flapping）：只有當網路恢復並持續穩定運行滿 STABLE_RESET_TIME=1800s（30 分鐘） 後，退避階梯才會重新歸零回 gradient=1，防止基站間歇性閃斷導致系統陷入高頻重啟循環。

4. 低功耗休眠與喚醒防殺機制（quectel-sleep）

• 休眠前（pre）：先停看門狗與撥號進程防止搶佔串口，再發送純記憶體指令 AT+QSCLK=1（不寫入 Flash，零晶片壽命損耗）並將 USB power/control 設為 auto，使模組進入低功耗休眠同時保留來電/簡訊硬體喚醒能力。
• 喚醒後（post）：立即恢復 USB 供電狀態為 on，並巧妙使用 systemd-run --no-block --unit=quectel-resume-recover 啟動一個脫離 systemd-sleep 生命週期限制的獨立臨時單元，延遲 5 秒 待 USB 枚舉穩定後再安全拉起撥號與看門狗（完美避開傳統在 post 腳本直接啟動服務會被 systemd-sleep 連帶終止的經典坑點）。

三、 日誌生命週期與 Flash 保護機制

• 滾動截斷保護：log_msg 在每次寫入 /mnt/data/cellular_guard/watchdog.log 時即時檢查檔案大小；一旦超過 MAX_LOG_SIZE=100KB，自動保留最新一半行數並原子替換（mv -f），在長期無人值守（如數年工業現場部署）下絕不會寫滿 /mnt/data 分區。
